# Demo — deepfake-detection + ZKP provenance CLI prototype

End-to-end command (Step 5): one audio file in → (1) AASIST-L deepfake
score, (2) SHA-256 of the exact file bytes, (3) a Groth16 proof binding the
file hash as public inputs with the v3 provenance circuit, (4) an
independent verification process — with a manifest of stage timings and
artifact paths on disk.

## What this demo establishes, precisely (read this first)

| Statement | Status |
|---|---|
| A Groth16 proof verifies under the **trusted, pinned** verification key | ✅ enforced by `snarkjs.groth16.verify === true` (local library call, not output parsing) |
| The file you point the verifier at hashes to the proof's public limbs | ✅ enforced — the verifier recomputes SHA-256 over the supplied file bytes and compares both 128-bit limbs |
| Provenance metadata satisfies the circuit rules (device/time/gate GPS/sensor) | ✅ enforced **in-circuit** (`valid_claim === valid`): generation fails if a rule is violated while claiming validity |
| Who captured the audio / that the metadata is TRUE | ❌ **not proven** — metadata values are supplied by whoever runs the CLI; the circuit proves they pass the rules, not that they reflect a real capture |
| The AASIST-L detector's verdict / model identity is cryptographically enforced | ❌ **not enforced** — the detector runs first and its score/decision/checkpoint-hash are **recorded** into `demo_result.json`, but the ZK circuit does not contain them and no proof binds them |
| "Authentic audio" | ❌ never claimed — success wording is scoped to *proof verification + file binding* |

## Prerequisites

- **Node.js ≥ 18** (developed on 24.19.0). Local dependencies install with:
  ```
  npm install
  ```
  ⚠️ **`snarkjs` is pinned at `0.7.6` in `devDependencies`** — a plain
  `npm install` installs it, but an installation with `--omit=dev` /
  `--production` will NOT have it and both the combined CLI and the
  independent verifier will fail at import. Do not strip devDependencies.
  (No global snarkjs/circom needed at demo runtime: proving and verification
  both use the local library through explicit API calls.)
- **Python ≥ 3.12** with the audio stack: `pip install -r audio_benchmark/requirements.txt`
  **plus `torch>=2.0`** (measured working: torch 2.8.0+cpu; the requirements
  file lists it commented "optional" for the placeholder backend, the AASIST
  backend requires it).
- **AASIST-L assets** (paths configurable by flags/env — never hard-coded):
  - upstream repo clone (`--aasist-repo`, env `AASIST_REPO`)
  - checkpoint `models/weights/AASIST-L.pth` (`--weights`, env `AASIST_WEIGHTS`)
  - config `config/AASIST-L.conf` (`--config`, env `AASIST_CONFIG`)
- **Frozen v3 artifacts (already in the repo, never regenerated by the CLI):**
  `outputs/v3/provenance_v3_js/provenance_v3.wasm`, `outputs/v3/circuit_v3.zkey`,
  and the verifier's pinned `outputs/v3/verification_key_v3.json`
  (vkey SHA-256 `cbae94c0fdbe0295ddf81e92f2e414c757babdd360064d65364c85a52f16e93c`).
  Rebuilding circuits/keys is NOT needed for the demo (that requires circom
  2.2.3 + the powers-of-tau file, out of demo scope).

(Provenance values above are the demo dataset row from `inputs/input.json`;

Exit 0 only after the independent verifier's own exit code is 0. The output

Artifacts written under the output dir: `input.json` (witness), `proof.json`,
`public.json`, `detector_output.txt`, `verify_output.txt`,
`demo_result.json` (stage timings, artifact paths, parsed detector result,
audio SHA-256 + limbs, tool/asset identity).

## Negative-path commands (measured)

| Scenario | Command | Measured result |
|---|---|---|
| Audio byte altered (on a **copy**), verified against the *original* run's proof | `node scripts/verify_media.js <tampered_copy.flac> outputs/v3/demo_honest/proof.json outputs/v3/demo_honest/public.json` | `[FAIL] hash binding: MISMATCH…` → REJECT, exit 1 |
| Proof modified, audio/public unchanged | same verifier on a doctored `proof.json` copy | `snarkjs.groth16.verify → false` → REJECT, exit 1 |
| Detector model missing | CLI run with `--weights C:/nonexistent/AASIST-L.pth` | `[error] detect: detector exited with code 1` → CLI exit 1, **no proof.json generated** |
| Missing audio file | CLI with a bad path | stage fail, exit 1, no output dir created |
| Existing output directory | CLI against an existing dir | `refusing to overwrite…`, exit 1 |
| Untrusted key offered | `node scripts/verify_media.js <audio> <proof> <public> --vkey outputs/verification_key.json` | vkey-integrity pin mismatch → REJECT, exit 1 |

Verifier suite: `node --test tests/verify_media.test.js` →
**12 pass / 0 fail** (includes real snarkjs API calls and the key-pin assertion).

## Architecture / trust notes

- `scripts/provenance_cli.js` — orchestrator; spawns the Python detector and
  Node verifier with **explicit argument arrays, no shell**; calls the local
  snarkjs API for proving; fails closed at every stage.
- `scripts/hash_limbs.js` — SHA-256 → two 128-bit decimal limbs (BigInt only).
- `audio_benchmark/detect_audio.py` — detector CLI (Step 2); reused verbatim.
- `scripts/verify_media.js` — independent verifier (Steps 4–4.1); reused
  verbatim; its trusted vkey pin is independent of any generated bundle.
- `circuits/provenance_v3.circom` — v3 circuit (frozen in Step 3): private
  device/timestamp/sensor/GPS rules + public SHA-256 limbs + public claim
  `valid_claim === valid`.

## Limitations (current prototype)

1. **Nothing proves the metadata is true** — only that it passes the rules.
2. **Detector not in the proof**: the hash limbs and metadata rules are the
   only in-circuit claims; AASIST verdict/score and checkpoint identity remain
   recorded-but-unsigned. A future step could commit the AASIST score (or the
   checkpoint hash) as an additional public input, but that requires a circuit
   change and new keys (rebuild, not patch).
3. **Groth16 keys are zero-contribution** (`groth16 setup` output, prototype
   convention; same as v2). Not ceremony-grade.
4. **File↔hash binding is verifier-side**: the circuit's public limbs bind the
   hash the prover *supplied*; `verify_media.js` closes the loop by recomputing
   the hash from the supplied file — but the circuit cannot itself attest file
   bytes (that would require in-circuit SHA-256 over preimages ≫ pot12 sizing).
5. **Demo metadata** (the five CLI values) comes from the synthetic dataset
   row, not a real capture device.
6. `pot12_final.ptau` supports up to 4,096 constraints; the v3 circuit uses
   458, leaving headroom only for similar-sized additions.
7. Windows-specific invocation paths exercised (explicit `process.exit` after
   snarkjs calls — its workers otherwise keep the process alive).
