# ZKP-Gated Media Provenance System

A research proof-of-concept that proves a media file's metadata satisfies
authenticity rules — **without ever revealing the raw metadata** — using
Zero-Knowledge Proofs (ZKPs) and a Circom/snarkjs pipeline.

---

## What This Project Does

When a camera or sensor captures a photo or video, it records private metadata
alongside the media: device ID, exact timestamp, GPS coordinates, sensor
quality score.  In traditional systems you must reveal all of this to prove
authenticity.  With ZKPs you can instead prove:

> *"This media was captured by an approved device, within the allowed time
> window, and the sensor quality was acceptable"*

…and a verifier can check that statement is true **without learning any of
the actual values**.

This MVP implements the first half of that pipeline:

```
CSV/XLSX dataset
      │
      ▼
validate_row.js   ← checks every rule (device, timestamp, GPS, score)
      │
      ▼
prepare_input.js  ← picks first valid row, writes inputs/input.json
      │
      ▼
inputs/input.json ← ready for Circom/snarkjs witness generation
      │
      ▼
hash_media.js     ← SHA-256 fingerprint of the media file
```

---

## How ZKP Provenance Works (conceptual overview)

```
Prover (camera owner)          Verifier (anyone)
─────────────────────          ─────────────────
knows: device_id=2048          sees: valid=1
        timestamp=1717350000
        sensor_score=85        cannot learn the raw values
        gps_lat=407900
        gps_long=778600
        │
        ▼
  ZK proof generation
  (circom + snarkjs)
        │
        ▼ proof.json + public.json
─────────────────────────────────────────────────
        │
        ▼
  snarkjs groth16 verify → ✓  (valid = 1)
```

The **circuit** (`circuits/provenance.circom`) encodes the rules as
arithmetic constraints.  The prover runs the circuit with their private
inputs to produce a proof.  The proof is a small (~200 byte) cryptographic
object.  Anyone with the *verification key* can check it without seeing the
inputs.

## Quick Start

### 1. Install dependencies

```powershell
npm install
```

### 2. Prepare the ZKP input file

Reads the dataset, finds the first row that passes all rules, writes
`inputs/input.json`:

```powershell
npm run prepare-input
```

Expected output:
```
=== ZKP Provenance — Input Preparation ===

Loaded 100 rows from: zkp_provenance_synthetic_dataset.xlsx

Selected row 1 (first row that passes all rules):
{ device_id: 2048, timestamp: 1717350000, sensor_score: 85, ... }

Circuit input (private signals — values become ZK witness):
{ device_id: '2048', timestamp: '1717350000', sensor_score: '85' }

Wrote: inputs/input.json
```

### 3. Validate a row

Shows which rows pass or fail each rule and why:

```powershell
npm run validate-row
```

Expected output:
```
=== ZKP Provenance — Row Validator ===

Row 1 (PASS) — will produce valid ZK proof
  Check results: { device_id: true, timestamp: true, gps_lat: true,
                   gps_long: true, sensor_score: true, overall: true }

Row 2 (FAIL) — failed checks: [sensor_score]
  Check results: { ..., sensor_score: false, overall: false }

Summary: 67 / 100 rows pass all rules.
```

### 4. Hash the media file

```powershell
npm run hash-media
```

Expected output:
```
=== ZKP Provenance — Media File Hasher ===

File    : ...\media\sample_001.jpg
Size    : 312 bytes
SHA-256 : e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

## Validation Rules

| Field         | Rule                                        | Circuit check |
|---------------|---------------------------------------------|---------------|
| `device_id`   | must be 1024, 2048, or 4096                 | ✅ implemented |
| `timestamp`   | between 1717300000 and 1717400000 (Unix s)  | ✅ implemented |
| `sensor_score`| ≥ 70                                        | ✅ implemented |
| `gps_lat`     | between 407800 and 408100 (scaled integer)  | TODO (circuit v2) |
| `gps_long`    | between 778400 and 778900 (scaled integer)  | TODO (circuit v2) |

GPS coordinates are stored as integers scaled by 10,000
(e.g. latitude 40.7900° → 407900) so the circuit can work with whole numbers.

## Next Steps — Full ZKP Pipeline

After this milestone the pipeline continues:

### Step 1 — Install Circom 2.0 compiler

```powershell
# Install circom binary (requires Rust)
# Windows: download from https://github.com/iden3/circom/releases
# or via cargo:
cargo install --git https://github.com/iden3/circom

circom --version
```

### Step 2 — Compile the circuit

```powershell
circom circuits/provenance.circom --r1cs --wasm --sym -o outputs/
```

Produces:
- `outputs/provenance.r1cs`   — constraint system
- `outputs/provenance_js/`    — WebAssembly witness calculator
- `outputs/provenance.sym`    — symbol map for debugging

### Step 3 — Trusted setup (Powers of Tau)

```powershell
# Download a pre-generated ptau file (saves hours of computation)
# https://github.com/iden3/snarkjs#7-prepare-phase-2
snarkjs groth16 setup outputs/provenance.r1cs pot12_final.ptau outputs/circuit_final.zkey
snarkjs zkey export verificationkey outputs/circuit_final.zkey outputs/verification_key.json
```

### Step 4 — Generate witness + proof

```powershell
snarkjs groth16 fullprove inputs/input.json outputs/provenance_js/provenance.wasm outputs/circuit_final.zkey outputs/proof.json outputs/public.json
```

### Step 5 — Verify the proof

```powershell
snarkjs groth16 verify outputs/verification_key.json outputs/public.json outputs/proof.json
```

Expected: `[INFO]  snarkJS: OK!`

### Step 6 — Add GPS to circuit (v2)

Uncomment the GPS signals in `circuits/provenance.circom` and add the
corresponding fields to `inputs/input.json` via `prepare_input.js`.

### Step 7 — Blockchain anchoring (future milestone)

Deploy a Solidity verifier contract (generated by snarkjs) to Ethereum/Polygon.
Anchor `proof.json` + the media SHA-256 hash on-chain so anyone can verify
the provenance claim without trusting a central server.

## Key Concepts

**Zero-Knowledge Proof (ZKP):** A cryptographic method where a prover
convinces a verifier that a statement is true without revealing any
information beyond the truth of the statement.

**Circom:** A domain-specific language for writing arithmetic circuits that
can be compiled into ZKP-compatible constraint systems.

**snarkjs:** A JavaScript library that runs the Groth16 proving system —
takes a circuit + witness and produces a compact proof.

**Witness:** The set of all private input values that satisfy the circuit.
In this project: `device_id`, `timestamp`, `sensor_score`.

**R1CS (Rank-1 Constraint System):** The intermediate representation of a
ZKP circuit.  Every constraint has the form `A * B = C`.
